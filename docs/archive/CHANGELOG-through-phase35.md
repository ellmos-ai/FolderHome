### Security boundaries

- No remote, push, release or public upload
- No unreleased file, network or telephone actions; live acceptance of phase 11 uses exclusively synthetic temporary folders
- FCSA live execution remains locked despite a planned filesystem report
- Document sources remain unchanged; local index write access is blocked without `--approve-index-write`
- OCR, external LLM syntheses and formatted report‑forge output remain separate extensions
- Version statements are blocked when the catalog document changes; no archiving suggestion is executed live
- Document action plans do not modify sources or target folders; a missing conversion provider and competing targets remain visibly blocked
- Transformations do not modify originals; OCR stays disabled and outputs outside TXT/PDF remain un‑blocked by a verified provider
- Folder observation writes nothing without a state gate, stores no raw document text and does not alter sources or profile rules
- Scan runs do not execute a scheduler or file action; an interval is only evaluated and a checkpoint is only added after tight approval
- Single‑file execution does not support cross‑volume fallback, overwriting, trash or automatic rule adoption
- A batch does not execute conflict‑laden documents and does not activate storage receipts after a successful rollback
- Routines do not register a scheduler and perform no file or checkpoint action without exact batch, file and state approval
- The multi‑watch queue declares `side_effects=[]`, does not change state or targets and reports `scheduler_registered=false`
- The scheduler handoff registers nothing; the runner writes only after the gate's own lock and run report and does not modify documents or checkpoints
